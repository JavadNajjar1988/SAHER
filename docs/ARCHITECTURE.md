# معماری سیستم ساهر (SAHER System Architecture)

این سند معماری پیاده‌سازی‌شده تا **مایلستون ۱.۵ (یکپارچه‌سازی، پایداری، امنیت و یکپارچگی داده)** را شرح می‌دهد.

## ۱. ساختار کلان (Modular Monolith)

```text
├── apps/
│   └── web/                        # واسط کاربری فارسی (React 19 + TypeScript 5.7 + Vite 6)
│       ├── vite.config.ts          # پروکسی توسعه (/api و /health به FastAPI روی 127.0.0.1:8000)
│       └── src/
│           ├── components/         # قطعات رابط کاربری (Sidebar, Preview, FileDetailModal, ImportDialog)
│           ├── services/           # کلاینت ارتباطی نوع‌داده‌دار (بدون بازگشت پنهان به localStorage)
│           │   ├── apiClient.ts
│           │   └── apiClient.test.ts
│           ├── types/              # تعاریف مدل‌های داده، وضعیت استخراج و وضعیت اتصال
│           └── main.tsx            # ریشهٔ برنامه و مدیریت وضعیت واقعی بک‌اند / حالت نمایشی مجزا
├── services/
│   ├── api/                        # وب‌سرویس محلی (Python 3.10+ + FastAPI)
│   │   ├── config.py               # تنظیمات سقف حجم آپلود، پسوندهای مجاز، CORS و حالت عملیاتی
│   │   ├── database.py             # اتصال SQLite با WAL، کلیدهای خارجی و مهاجرت ایمن ستون‌ها
│   │   ├── repository.py           # الگوی مخزن با دریافت جریانی (Streaming)، تراکنش اتمیک و FTS5
│   │   ├── schemas.py              # قراردادهای داده Pydantic
│   │   └── main.py                 # اندپوینت‌های REST نسخه ۱ (/api/v1)، محافظت Origin و هدرهای امنیتی
│   └── ingestion/                  # موتور اعتبارسنجی باینری، نرمال‌سازی فارسی و استخراج متن
│       └── extractor.py            # بررسی Magic Bytes، نرمال‌سازی ي/ك و نیم‌فاصله، استخراج TXT/PDF/DOCX
├── tests/
│   └── test_api.py                 # آزمون‌های خودکار یکپارچگی، امنیت، FTS5 و اتمیک‌بودن تراکنش‌ها
├── pyproject.toml                  # مشخصات تکرارپذیر وابستگی‌های پایتون و تنظیمات pytest
└── docs/                           # مستندات معماری و وضعیت توسعه
```

## ۲. اصول یکپارچگی داده و امنیت در مایلستون ۱.۵

1. **عدم بازگشت پنهان (No Silent Fallback)**:
   - در صورت قطع ارتباط با FastAPI یا بروز خطای HTTP، کلاینت فرانت‌اند خطای ساخت‌یافته (`ApiClientError`) پرتاب می‌کند و هرگز به طور پنهانی داده را در `localStorage` ذخیره نمی‌کند.
   - حالت نمایشی (`Demo Mode`) کاملاً مجزا و صرفاً با انتخاب صریح کاربر فعال می‌شود.
2. **جداسازی کامل آرشیو عملیاتی از داده‌های نمونه**:
   - آرشیو عملیاتی به‌صورت پیش‌فرض خالی (`0` فایل) آغاز می‌شود و هیچ رکورد نمایشی یا تصویر ساختگی در پایگاه‌داده اصلی تزریق نمی‌شود.
3. **خط لولهٔ امن واردسازی فایل (Streaming & Atomic Ingestion)**:
   - فایل‌های ورودی به‌صورت جریانی (Chunked Stream) با سقف حجم قابل تنظیم (`max_upload_size_bytes`) خوانده می‌شوند.
   - امضای باینری فایل (Magic Bytes) پیش از پذیرش بررسی می‌شود و فایل‌های اجرایی، HTML/اسکریپت و فایل‌های دارای پسوند جعلی رد می‌شوند.
   - در صورت بروز خطا در پایگاه‌داده، فایل منتقل‌شده بلافاصله از دیسک پاک‌سازی می‌شود تا فایل یتیم (Orphan File) باقی نماند.
4. **تفکیک معنایی متن استخراج‌شده از پیام‌های سیستم**:
   - فیلد `extracted_text` صرفاً حاوی متن واقعی استخراج‌شده از سند است.
   - اسناد PDF اسکن‌شده و تصاویر بدون متن با وضعیت `extraction_status = "pending_ocr"` و متن خالی ثبت می‌شوند تا نمایهٔ FTS5 با پیام‌های سیستمی آلوده نشود.
5. **جست‌وجوی تمام‌متن فارسی (SQLite FTS5)**:
   - یکسان‌سازی نویسه‌های عربی/فارسی (`ي`/`ی`، `ك`/`ک`) و پشتیبانی از نیم‌فاصله (`ZWNJ`) در زمان نمایه‌سازی و پرس‌وجو.
   - اعمال هم‌زمان فیلترهای نوع فایل (`kind`) و وضعیت (`status`) در کنار عبارت جست‌وجو (`query`) همراه با بازگرداندن بریدهٔ متنی (`matched_snippet`).
